## How to maintain this matrix

IDs are stable. Never renumber or reuse one; mark obsolete rows Superseded and link the replacement. “Target” paths and “Planned” checks are intentions, not evidence. Replace them with actual file/test names and artifact paths as work lands.

Every path in the tables is repository-relative. For compactness, an unqualified E2E spec basename
resolves under `tests/e2e/`, a server test basename under `apps/server/test/`, a Web component/page
test under `apps/web/src/`, and a shared engine/model test under `packages/shared/src/`. The full
command chronology and measured environment live at `docs/progress-log.md`; visual review IDs and
exact PNG paths live at `docs/ui-rubric.md`.

Status vocabulary:

- **Planned:** requirement accepted; no complete implementation-and-verification evidence yet.
- **In progress:** implementation exists but required verification is incomplete or failing.
- **Verified:** implementation, automated checks, and applicable manual/visual evidence all pass; record evidence.
- **Blocked:** an external prerequisite is absent and safe local work cannot close it; state the exact blocker.
- **Cancelled/Superseded:** requires user-approved scope change and a decision-log link.

No row may become Verified from file presence alone. `Verified` rows below are limited to requirements
whose applicable automated and document/manual review evidence is current. Platform claims remain
conservative: pinned Chromium/WebKit automation is not evidence for two separately installed
historical browser majors, Web Audio instrumentation is not physical Safari listening, and macOS
launcher automation is not Windows/Linux execution or a Finder double-click/browser-open rehearsal.
